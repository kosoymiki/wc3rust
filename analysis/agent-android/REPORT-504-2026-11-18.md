## 4. Defects found (cross-lane, patch included, not edited by this lane)

### D1 — every checkpoint this build writes is unreadable (P0, blocks save/load)

```
02:20:20.600  GAME_RESUME_FAILED path=/data/data/org.wc3rust.p0/files/wc3rust-resume.sav err=UnknownVersion(8)
```

`crates/wc3-sim/src/save.rs`: `SAVE_FORMAT_VERSION = 8` (line 143) and
`open_envelope` accepts `1..=SAVE_FORMAT_VERSION` (line 5455), but
`Sim::from_save` (lines 5536-5549) matches only `1 => … 7 => decode_v7(…)` and
sends everything else to `SaveError::UnknownVersion`. A version-8 file therefore
fails to load on the same build that wrote it. `decode_payload(payload, 8)` already
exists behind the version gate, so the fix is the missing arm:

```rust
/// Decodes the current version-8 payload: the per-unit in-flight building
/// upgrade (`UpgradeJob`) appended to each unit record.
fn decode_v8(payload: &[u8]) -> SaveResult<Sim> {
    decode_payload(payload, 8)
}
// …
            7 => decode_v7(payload),
            8 => decode_v8(payload),
```

Owned by lane 501/507 (`crates/wc3-sim/**`), hence reported, not edited.
Effect on the host: the write path is proven (`GAME_CHECKPOINT
path=…/wc3rust-resume.sav`, 709 225 B + `.meta`, three times in §1), the read
path is not, so pause/resume-restore stays unproven until this lands.

### D2 — Orc01 full-roster residency (P0 for the 350 MB gate)

`crates/wc3-game/src/assets.rs:1067-1071` (`map_model_scope`): `unresolved =
scope.script_calls - scope.script_literals > 0` → `ModelScopeMode::FullRoster`.
Orc01's script has such calls, so 821 models / 1370 textures are resident even
though the mission spawns ~17 units. The assets layer already has the documented
escape hatch for late ids (`Assets::ensure_model`, assets.rs:2573-2581), so a
bounded residency (map-scoped start + `ensure_model` when the script actually
creates a def) keeps the chapter playable at Melee-like memory. Numbers in §3.

### D3 — stale package path in `find_file` (fixed in this lane)

`apps/android-native/src/lib.rs` searched `/data/data/org.wc3rust.p0/files`
before its own `data_dir()` and `data_dir()` itself hardcoded one package id, so
after the rename round-trip the app looked in another package's directory.
Now `package_name()` reads `/proc/self/cmdline`, `data_dir()` uses it, and
`find_file` searches `data_dir()`, the external dir of the same package and
`/sdcard` — no hardcoded id (fallback const only for a non-Android harness).
