# SIM GAPS — 2026-11-18 (lane 501 census)

Scope: what a player actually does in a WC3 match versus what `crates/wc3-sim`
can execute, per race. Sources are the shipped tables only: the generated
roster (`crates/wc3-sim/src/roster_gen.rs` ← `Units/UnitData.slk`,
`UnitBalance.slk`, `UnitWeapons.slk`, `*UnitFunc.txt`), the upgrade sheet
(`upgrades_gen.rs` ← `Units/UpgradeData.slk`), items (`items_gen.rs` ←
`Units/ItemData.slk`), shops (`shops_gen.rs` ← `Sellitems=`/`Makeitems=`), and
the sim code itself.

Method: counts are parsed from the generated tables (no hand-typed numbers);
"sim implements" is decided by reading the code path and is confirmed by a test
in `crates/wc3-sim/tests/sim_parity_501.rs` / the existing suites. Anything not
confirmed by a run is labelled `unknown`.

## 3. What the two failing `sim_bridge` menu tests proved

`scripts/h2-cargo test -p wc3-game --lib menu` (tech-lead run, 2026-11-18)
failed `sim_bridge::tests::build_menu_is_slk_derived_and_affordance_aware` and
`every_def_is_reachable_from_the_roster_menus`. Root cause found by reading the
data, not the test: once `is_worker_buildable` correctly excludes every
`Upgrade=` form, the human build menu no longer contains `hgtw`/`hctw` (they are
the Scout Tower's upgrade forms), and the tower slot had no damage-dealing
worker-buildable candidate at all. Fix:

* `data::build_menu` defence slot now accepts a base form whose **`Upgrade=`
  targets** deal damage (`hwtw`), so the peasant gets the Scout Tower again;
* the menu test pins `menu[1] == "hwtw"`, asserts `hgtw` is *not* a placement,
  and proves the War Mill gate through `Sim::upgrade_denial(hwtw, hgtw)`;
* the reachability test now accepts the three legitimate sources — build entry,
  data upgrade chain, spell placement — **and** asserts the sim accepts each
  upgrade (`upgrade_denial == None`) instead of only checking the menu list.
