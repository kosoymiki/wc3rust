## Defects found and fixed (mechanism → fix)

1. **Orc01 loaded the whole 823-def roster (ledger 504's PSS blocker).**
   `script_created_ids` matched the `createunit` prefix inside the user
   functions `call CreateUnitsForPlayer0/5/7/11(  )`, counted them as four
   unresolved unit creations and fell back to `scope=full` (822 models,
   349 MB of textures, +17 s). Identifier matching is now explicit
   (`CreateUnit` exact; `CreateNUnitsAtLoc*` and `BlzCreateUnit*` prefix), so
   Orc01 is `mode=map … loaded=36 skipped=786` and the lane suite went from
   168 s to 63 s. `crates/wc3-game/src/assets.rs:1127-1200`,
   tests `script_scope_tests::*`.

2. **An authored "no model" sentinel was logged as a missing file.**
   `DestructableData` gives the LOS blocker `nzin`
   `Doodads\Terrain\LOSBlocker\InvalidFileOnPurpose.mdx`; the Orc01 load logged
   `model_failed=… id=nzin` and built a placeholder box for an invisible wall.
   `is_authored_empty_model` (`assets.rs:1207`) now records `model_empty=` and
   skips the placeholder. `model_meshless=0`, `missing=0`.

3. **Missing model textures were silent.** `load_model_textures` bound the
   white mask on a decode error with no log (`Err(_) => map.push(0)`). It now
   logs `texture_failed=<path> error=…` once per path
   (`assets.rs:3205-3265`), including from the lazy `ensure_model` path.

4. **`StormSource::exists` ignored loose installs.** It asked `StormFs::info`
   (archives only), so `GameDatabase::load_profiles` reported every loose-tree
   profile as missing and `GameDatabase::missing` counted tables that exist.
   Now `self.fs.exists(path)` (`assets.rs:1530`).

5. **HUD pack was never found on the device.** `pack_search_dirs` hardcoded the
   old package id `org.wc3rust.p0` and never looked next to the open archive.
   Added `find_installed_near(install_root)` (`hudskin/pack.rs:259`) — checked
   first in `Assets::load` — and both app ids are listed. On the device the pack
   is now `…/files/hud_pack` with 92 assets, 5 fonts, 24 roles.

6. **No packaged asset hash check.** `verify_pack` (`hudskin/pack.rs:337`) reads
   `SHA256SUMS.txt` (102 files on the device pack), re-hashes every file, and
   `HudPack::load` fails with `HUD_PACK hash=<file> expected=… actual=…` when a
   manifest asset differs; documentation-only mismatches are logged
   (`hash_mismatch=`) but do not take the HUD down. Load log now reports
   `hash=102 hashed_bytes=5671496`.

7. **The map registry only knew `donors/maps/melee`.** `map_registry` gained
   `origin` provenance, `build_install` (recursive `Maps/` tree + every
   `.w3m/.w3x` entry of `War3.mpq`, `War3x.mpq`, `War3xlocal.mpq`),
   `resolved_path`, `archive_map_entries`, `extract_archive_map` (temp+rename
   into `$TMPDIR`), and `players_for_file` (header-only `sloc` count).
   Generated artifact: `analysis/maps/REGISTRY-INSTALL.json` — **123 maps,
   0 rejected** (38 melee + 44 RoC chapters + 41 TFT chapters).

Chaos/edge cases covered: a map entry that is not a map, an archive without a
listfile, a missing file (typed `FileNotFound`, never empty bytes), a pack with
no `SHA256SUMS.txt` (`hash=unverified`), a tampered pack asset (fatal), a docs
mismatch (non-fatal), roaming `War3_*.mpq` LOD packs (not mounted as layers).

## Shared tooling defect (blocks every lane)

`scripts/h2-cargo` was edited **in place** twice while wrappers were running:
bash resumes reading at a byte offset, hit `syntax error near unexpected token
'('` (line 82) and later `'done'` (line 110), killing queued jobs and the APK
build (`apk-0318d.log`, `check_rc=2`). A `su -c` run also created the shared
queue log root-owned (`h2-cargo.log`, permission denied for u0_a394). And
`trap cleanup EXIT INT TERM` does not exit on TERM, so a TERM-ed wrapper keeps
its queue ticket and the slot logic wedges until `timeout -k` KILLs it.
Recommended fixes (not applied here — file is shared and was under active
edit): write the script via temp+rename, `trap 'cleanup; exit 130' INT TERM`,
and fall back to a per-user log when `$LOG` is not writable.
