## 2. `sync_visuals` verification (game.rs, read-only)

Current code (`crates/wc3-game/src/game.rs:2065-2125`):

* **Correct (tech-lead fix):** the animator is built from the per-def MDX
  (`assets.model_for_def(def_id)`, :2078-2089) — geometry and skeleton now come
  from the same file.
* **Defect 1 — sequence from the wrong MDX:** the sequence is resolved through
  `self.assets.model(*kind)` (:2101, four-kind model) while the animator plays
  the per-def model. A per-def model may not contain the four-kind sequence name
  (or has different timing), so walking/idle can play a name from another
  model. Fix: resolve with `assets.model_for_def(def_id)`.
* **Defect 2 — construction:** `wanted` is `SequenceKind::Idle` for every
  building (:2085-2087) regardless of `construct.is_some()`; a building under
  construction must play `Birth` (one-shot, hold last frame) and switch to
  `Stand`/`Stand Work` when finished.
* **Defect 3 — death:** `self.visuals.retain(|id, _| live.contains(id))`
  (:2123-2124) drops the visual the moment the unit leaves `alive_units()`;
  the death animation never plays. Fix: keep a per-visual death window (play
  `Death` once, hold ~1.2 s, then remove).
* **Defect 4 — attack while walking:** `(*cooldown > 0 && !path_empty)` selects
  `Attack` (:2089-2093) even when the unit is moving; a moving unit with a
  running cooldown must keep `Walk`. Priority is encoded in
  `wc3_anim::select_state` (tests `assets_anim_ingame`).
* **Defect 5 — no cast/channel:** casting/channelling units keep idle/walk.
  `GameplayState::Cast/Channel` are resolved strictly by the registry.

`game_state_patch.md` (same directory) has the exact replacement code; the
runtime side is already implemented and tested:

* `wc3_anim::GameplayState` (+ `Build`, `Birth`), strict
  `state_sequence/state_animator/state_resolutions` (registry.rs:193-500).
* `wc3_anim::select_state` / `hover_uses_idle` (state.rs) — corrected priority:
  dead > constructing (Birth) > channel > cast > building attack > worker build
  > standing attack > walk (walk beats cooldown) > idle.
* `Animator::update` now holds non-looping sequences (`flags & 1`: Death,
  Birth) at the last frame instead of wrapping (lib.rs:415-437), so a corpse or
  a spawned building does not snap back to the first pose.

    currently mid-edit (`mapcontent.rs` missing `Reader::skip`) and a

    layer settles.
* **Asset-path finding:** resolution requires case-insensitive path lookup —
  the extracted tree stores `LordaeronTree0.mdx` with mixed case and archives
  may use `.MDX`; `doodads.rs::load_model` calls `StormFs::read(candidate)` with
  exact case and only the candidate list we mirror. Recommended fix (world
  owns doodads): after the exact candidates fail, retry with a case-insensitive
  name table (or add the `.MDX`/`stand` suffix variants). Evidence: with
  case-insensitive lookup 35/35 ids resolve; the diagnostic in
  `world_audit.rs:1290` still reports only placed scales, not model-resolution
  counts.
