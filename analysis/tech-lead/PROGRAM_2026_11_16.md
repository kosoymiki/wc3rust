## 1. Reflection — why the port is not playable yet

**Goal / invariants.** A player must be able to run a WC3 melee match on `(2)Justice.w3x` with the
retail loop: worker economy → tech tree → army → combat → win/lose; heroes with four abilities and
levels; shops and a backpack; fog, minimap and audio; and it must stay under the mobile memory budget
(measured 283 MB PSS on device).

**Mechanism (file:line).** The read-only parity audit (`PLAYABILITY_GAP_2026_11_16.md`, 168 verified
refs) found the hard blocker in the *UI→sim bridge*, not in the engine:

- `game.rs:4826-4838` × `game.rs:2141-2153` — `UiAction::TrainDef` is gated on `selected_hall()`, so a
  barracks card renders units and the tap silently no-ops. **No human combat unit can exist.**
- `hud.rs:1787-1792` — hero skill points cannot be spent; `lib.rs:4508` — `revive_hero` has no caller.
- `abilities.rs` implements 31 `Spell` variants for 763 ability rows; the rest are data-only.
- `shops_gen.rs` holds one row, so no shop sells anything.

**Root cause (5 whys).** Why is it not playable → no army → training is routed to the hall only → the
card was written for the hall's own menu and never generalised to "selected producer" → there was no
contract test that walked *card tap → unit exists* → the acceptance suite tested `sim.train_def`
directly. The same shape repeats in every gap: the sim has the verb, the card has the row, and nothing
asserts the bridge.

**Blast radius.** Fixing the producer gate touches `game.rs` only; the hero/shop/build work touches
`wc3-sim` data + `game.rs` card population; the campaign work is additive (`cinematic.rs`, `campaign.rs`).
Device installs are unaffected until the next APK.

**Falsification.** "Playable" is false until, in one device run: a barracks tap produces a footman and
debits 160 gold; an altar tap produces a hero; a skill point is spent from the card; a shop purchase
lands in the backpack; and the match reaches a score screen.

**Named verification.** `production_card_producer_trains_from_barracks`, `hero.altar.menu-per-race`,
`hero.learn.spends-point`, `items.shop.catalogue-per-race`, `maps.registry.all-load`,
`campaign.scaffold.parses-human01`, plus `HUD_LAYOUT_GATE PASS` and the memory gate.

## 3. Mobile constraints (non-negotiable)

- Touch targets: 95 px tiles (36 dp) at the retail 29.3% console; nothing below 90 px on the shorter side.

- Thermals/CPU: 60 FPS at 2414x1080 on Turnip; headless runs need `SDL_AUDIODRIVER=dummy`.
- Storage: maps and CGI stay under `analysis/` / device files, never in a release artifact.

## 5. Reforged balance

The port's numbers come from TFT 1.31 SLKs (`analysis/war3_full*`). Reforged 2.x changed hero and unit
balance. Plan: a **balance overlay** table (`analysis/balance/reforged-2.x.json`) applied at roster
generation time — never hand-edited into `roster_gen.rs` — sourced from the official patch notes
(fetched with the stealth-browser MCP, URL + date recorded), one row per changed field
(`hp/armor/damage/cooldown/cost/upgrade`), with a test that every overlay row matches an existing def
field. Until the overlay lands, the shipped numbers are TFT and the HUD says so.
